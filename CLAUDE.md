# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`farsi2epub` converts Farsi (Persian) PDF books into RTL EPUB 3 ebooks using Claude vision models to transcribe page images. It is a CLI (`click`-based) installed as an editable package.

## Commands

A virtual environment exists at `venv/`; activate it before any Python command:

```bash
source venv/bin/activate
pip install -e .          # editable install (entry point: farsi2epub)
```

### Shell completion

click 8 auto-generates tab completion for the `farsi2epub` entry point. Add to `~/.zshrc` (or `~/.bashrc`, using `bash_source`):

```bash
eval "$(_FARSI2EPUB_COMPLETE=zsh_source farsi2epub)"
```

The CLI stages operate on a per-book workspace identified by a slug; QC and human review are optional:

```bash
farsi2epub analyze <pdf> [--slug s] [--pages 3-10] [--force]   # create workspace, classify PDF, estimate cost
farsi2epub transcribe <slug> [--pages ...] [--force] [--max-cost N] [--concurrency 4] [--model ...] [--qc auto|manual|skip|ask] [--yes]  # --yes skips the auto-QC cost prompt
farsi2epub qc <slug> [--mode auto|manual] [--all] [--yes] [--force] [--pages ...]  # auto = LLM verifier pass (suggest-only), manual = review UI
farsi2epub review <slug> [--all] [--reset] [--background|--status|--stop] [--no-bbox-refine] [--bbox-refine-model ...]  # local web UI for human correction; -b detaches the server
farsi2epub build <slug>      # assemble EPUB into books/<slug>/out/
```

`epubcheck` is run automatically after `build` if it's on PATH (optional).

**Scoping and budget defaults are per-stage and do not compose — verified in `cli.py`, not inferred:**

- `analyze --pages` writes `page_range` into `book.yaml`, and `transcribe` falls back to it (`cli.py`: `spec = pages_spec or meta.get("page_range")`). Passing `--pages` explicitly at each stage is the safer habit, since an existing workspace carries whatever range it was created with.
- `transcribe --qc auto` does **not** QC every page it transcribed. It calls `qc.run_qc(...)` without `all_pages`, so QC risk-selects: forced (needs_review or any validator issue) + risky (`risk_score >= RISK_THRESHOLD`) + a `RANDOM_SAMPLE_FRAC` sample of clean pages. Full coverage is only reachable via the standalone `farsi2epub qc --mode auto --all`.
- `--max-cost` guards **`transcribe` only**, and is a running total of actual spend checked as pages complete — in-flight pages still finish, so it can overshoot by up to `--concurrency` pages. Auto-QC and bbox refinement bill separately and are not counted against it.
- `review` has **no `--pages`**; it reviews whatever was transcribed, and surfaces only the worst `ceil(total/5)` flagged pages unless `--all` (the rest are auto-accepted with `review_skipped: true`).
- Auto-QC re-runs **skip** pages whose previous suggestion is still pending; `--force` replaces it.

### bbox accuracy loop (`tests/bbox_score.py`)

Automated accuracy measurement for the review UI's boxes. **The VLM transcribes, Python grades** — the model is never asked "is this box right?", only to read what is printed; the verdict (`exact`/`partial`/`shifted`/`wrong_line`/`wrong_region`/`no_box`), `shift_words` and the golden metric below are then computed deterministically.

**The golden metric is word-miss distance** (`_word_miss_distances`). For each word that must be inside the box: 0 if the box covers it, else the **word distance to the nearest covered word**, in reading-order index space. English illustration — sentence `my father bought some milk`, target word `milk`, box covers `my father`: the nearest covered word is `father` at distance 3, so `milk` scores 3. The objective for every correction and in aggregate is **zero**.

- **Headline is `perfect_rate`** — the fraction of corrections scoring exactly 0 — reported over the **full graded denominator**, with every degenerate case (`no_box`, `no_covered_words`, `wrong_region`, `phrase_absent`) counted as not-perfect. That is what preserves the old `acc@1` invariant: turning a wrong box into no box can never score as a win.
- **Magnitude** (`word_miss_mean`/`median`/`p90`/`histogram`) is computed over **measured cases only**. Degenerates are deliberately *excluded from the magnitude* rather than given a synthetic penalty: a page-length-scaled penalty was rejected because page length varies by book, so the same locator failure would score differently per book and destroy cross-book comparability. `word_miss_penalized_rate` reports their share separately and is gated to non-increase.
- **The metric is unbounded above and heavy-tailed. Never read the mean alone.** Measured: `haaji-agha` has the *worst* mean (13.06) and the *best* `perfect_rate` (0.882) — three catastrophic cases carry the entire mean while p90 is 0.0. Read `perfect_rate` and `word_miss_histogram`.
- **`geom_unconfident` is a judge failure, not a locator failure.** When the reading-to-ink line pairing drifts under a case's own box (`geom_drift_tainted`), the grade is untrustworthy in either direction, so it is tagged `degenerate: geom_unconfident`: NEUTRAL (excluded from the magnitude and from `word_miss_penalized_rate`, so a broken judge cannot be read as a broken locator) but still inside `perfect_rate`'s denominator, so it can never read as a win. Its rate is capped at 3% by `--gate`, mirroring `judge_unusable_rate` — if it climbs, the alignment is broken and the headline is being computed on a self-selected survivor set.
- **An over-wide box costs nothing, by design.** Box width is a separate, milder cosmetic defect and must not be allowed to dominate the objective. Consequence: nothing gates against a locator "winning" by widening correctly-placed boxes to span whole lines. `mean_iou` is the only reported signal that would move on such a change — check it by hand before accepting a change justified on word-miss alone.
- Distance is **reading-order index space, not screen coordinates** (the text is RTL), so it crosses line boundaries: the last word of one line and the first of the next are distance 1 apart. Intended.
- `acc@1`, `acc@0` and the verdict buckets are still reported and still gated, but are no longer the objective. `acc@1` forgives a ±1-word miss and is dominated by an unrelated box-width defect — it read 0.7957 on the frozen sample where `perfect_rate` read 0.7021, and it rated `boof-e-koor` at 0.659 while 27% of that book's boxes covered *nothing at all*.

Frozen-sample baseline of record: **`out/score_word_miss_baseline_v4.json`** (`_SCORE_CACHE_VERSION` 4) — overall `perfect_rate` 0.817, mean 5.49, p90 0.0, penalized 8.1%, `geom_unconfident` 1.3%, `acc@1` 0.8638. By book — `Hossein_shenasi` 1.0 (n=1, meaningless), `haaji-agha` 0.882, `bachehaye_ghali` 0.805, `boof-e-koor` 0.796. By tier — `scan_vlm` 0.884 (n=172), `match` 0.867 (n=45), `scan` 0.0 (n=5). `tests/word_miss_smoke.py` and `tests/bbox_judge_regression.py` both assert against this file; regenerate it and rebase their constants together, never one alone.

**A superseded claim, recorded so it is not re-derived:** an earlier baseline reported the `match` tier at 0.444 perfect / 22.2% degenerate and concluded the Unicode-text-layer path was weaker than the image-scan path. That was false — it was the geometry-source routing bug (see `_layer_geometry_usable`), which forced every `boof-e-koor` page onto scan geometry that covered nothing. `match` is 0.867. Do not demote a tier on a cross-tier comparison without first checking the tiers are not confounded with book: in this corpus no book is scored on more than one tier, so a per-tier difference is a per-book difference until an experiment separates them.

**This baseline replaced `out/score_word_miss_baseline.json` (0.6936 / 7.76 / p90 6.0 / `acc@1` 0.7787) because THE MEASURING INSTRUMENT CHANGED, NOT THE LOCATOR.** The judge had been reading correctly-placed boxes out against the wrong printed line (see `_split_tall_runs` below); repairing that re-graded 13 of 240 cases, 12 of which sat on a demonstrably drifted alignment before the fix. The same applies to the v2 -> v3 step (geometry-source routing, +24 cases on `boof-e-koor` alone). The v3 -> v4 step is the ONE that did move boxes: bumping `review._LOCATE_VLM_CACHE_VERSION` to 3 moved 45 of 240 boxes, `perfect_rate` 0.783 -> 0.817, p90 1.0 -> 0.0. Do NOT read an instrument fix as locator progress, and do NOT run `compare --gate` across the two: the gate is built for "instrument fixed, locator changed" and this is the reverse. Old reports remain readable on their old fields; they are not comparable on the new ones.

**Truth is per PAGE, never per box.** This is the load-bearing invariant. The answer key is a full-page reading frozen in `books/<slug>/locate_page_read.json`, keyed on `(slug, page, render geometry, model)` — it mentions no box, so no locator change can invalidate it and iterations are free and perfectly comparable. Pages with a clean Unicode text layer skip the model entirely (PyMuPDF's word rects rebuild the key for free every run, `truth_source: pdf_words`); cipher/scan pages need one whole-page read (`vlm_page`). The superseded `--judge cached` path keyed readings on the *crop around the box under test*, so a structural change moved every crop and silently dropped half the sample from every denominator — that is what `score` now refuses to do (`_MAX_EXCLUDED_FRACTION`).

Acquisition (once per page, ever) and scoring:

```bash
# 1. acquire the answer key for any page that lacks one (subagents read the PNGs)
./venv/bin/python tests/bbox_score.py pages --cases tests/data/bbox_cases.json \
    --sample 240 --seed 7 --stratify book,tier,kind --out-dir out/pagekey
#    ... a Claude Code subagent reads each out/pagekey/BATCHES/batch_NN.json ...
./venv/bin/python tests/bbox_score.py ingest-pages --manifest out/pagekey/manifest.json \
    --readings out/pagekey/readings/
# 2. score the FROZEN sample — fully offline, free, repeatable, fixed population
./venv/bin/python tests/bbox_score.py score --cases tests/data/bbox_sample240.json \
    --out out/score_NNN.json
# 3. compare two iterations
./venv/bin/python tests/bbox_score.py compare --baseline A.json --candidate B.json --gate
```

Guardrails, each of which exists because it failed in practice:

- `ingest-pages` **verifies the answer key on acquisition**: every reading is scored against that page's own independent transcription (`text/NNNN.md`) by `_page_recall`, and anything below `_PAGE_RECALL_MIN` (0.85) is rejected and reported for re-reading at tile resolution. Measured on `bachehaye_ghali`, whole-page readings land at 0.91–1.00.
- `score` **refuses to write a report** when more than `_MAX_EXCLUDED_FRACTION` (10%) of the sample has no grade, instead of warning and emitting a number computed on a biased survivor subset. `--allow-thin-denominator` overrides; the result is not a valid baseline.
- `compare` **refuses to diff reports with different `truth_sha1`** (`--allow-truth-drift` overrides): two runs are only comparable if they graded against the same frozen readings.
- **Score the frozen sample, not a fresh one.** `tests/data/bbox_sample240.json` is an explicit 240-case list; score it with **no `--sample` flag**. `--sample N --stratify book,tier,kind` re-samples per run and strata on `tier`, which is an *output* of the locator — so a change that moves boxes between tiers silently changes its own population. Measured: enabling Tier C refinement under `--sample` shifted the sampled set (14 cases uncached, per-book counts moved) and reported 0.6923; the same treatment on the frozen sample reports 0.6723 with 0 uncached. Case identity is the hunk, which no locator change can alter, so a frozen id list is stable forever.
- `compare` reports **Wilcoxon signed-rank p** over the paired per-case word-miss deltas (the golden metric is continuous, so a binary test does not apply to it), and retains **McNemar's exact p** for the binary `perfect_rate` indicator. Both are printed; the gate keys on Wilcoxon. scipy is deliberately not a dependency — `_wilcoxon_signed_rank_p` is a hand-rolled normal approximation with continuity correction and tie-corrected variance over `math.erf`. It returns `None` below 10 non-zero deltas and is advisory below 25.
- Paired case counts are the only evidence a change carries: "3 fixed, 0 broken" is p=0.25, i.e. noise. Detecting a true 3-point shift at 80% power needs ~15–25 discordant pairs, so keep ≥150 *scored* cases per comparison. Wilcoxon pairs only cases **measured in both reports**; `compare` prints how many were dropped for that reason — read that count before trusting the p.
- `compare --gate` is layered, never swapped. It requires `perfect_rate` to improve with Wilcoxon p<0.05 (an underpowered test **fails**, it does not pass silently), caps `acc@1` regression at 2 points as a guardrail against a locator winning on placement by drawing wrong-line boxes, forbids `word_miss_penalized_rate` from increasing, and keeps every pre-existing check (per-tier `acc@1` cap, `no_box_rate` non-increase, `judge_unusable_rate` 3% cap, golden-case IoU). The old "overall `acc@1` must improve" condition became the 2-point regression guardrail: keeping both made the gate unsatisfiable for any change that trades width for placement.
- `_align_line_sequences` aligns reading lines to detected ink lines monotonically (Needleman–Wunsch). Requiring equal line counts and otherwise spreading the reading char-proportionally over the page — the crop-era fallback — cost 15 points of acc@1 at page scale, because one undetected line discards the correspondence for all ~900 words.
- **The aligner reconciles a line-count deficit by dropping a line MID-PAGE, and everything after the drop is then graded against the wrong ink.** Measured on `bachehaye_ghali` p64: two printed lines whose ascenders and descenders touch produce one 62px row run against a 27px reference, so 28 detected lines met 29 printed ones; the aligner dropped reading line 4 and three pixel-verified-correct boxes graded `wrong_line` with word-miss 27/50/17 instead of 0/0/≤1. Two defences, both required:
  - `locate._split_tall_runs` (Tier C, **shared production code** — it moves real boxes in the review UI, not only grades) splits any row run taller than `1.6 * H0` at the minimum-ink row of its middle third, provided that row is a genuine valley (≤ half the run's median ink) and both halves are ≥ `0.5 * H0`, recursing at most 3 deep. `H0` is the median of the **unmerged** raw runs so a fused pair cannot inflate its own reference. A heading or drop cap has no valley and is left intact. This alone cut `geom_unconfident` from 10.2% to 3.0% of the frozen sample and lifted `acc@1` 0.7787 → 0.7957.
  - `_assign_word_rects` latches a **drift** flag at the first pairing discontinuity and marks every word from there on unconfident. It latches forward only, positionally: the printed folio is routinely absent from the Markdown, so a drop on the LAST line is the common case (124 of 136 sampled `bachehaye_ghali` cases) and must not blank out the page above it.
- **`geom_confident` gates now; it used to be recorded and ignored.** The gate is drift, not the flag itself: `geom_confident` also folds in `_counts_close`, a routine word-segmentation difference that flags 33.6% of the frozen sample and can never meet the 3% cap, whereas drift-tainted boxes are 3.0%. Restoring the full page-level AND (page confidence AND local) was measured at 76.2% excluded — the page-size effect below, in a new disguise. Only `_Alignment.structural` (could the sequences be aligned at all; did too many reading lines go unpaired) is ANDed page-wide.
- `geom_confident` is reduced over the words the case actually rests on, not the whole image; at page scale the global version measured page size rather than alignment quality.
- **A case is "measured" for the golden metric only when `degenerate is None`.** A `wrong_region` case can have both index sets and would otherwise produce a `word_miss_sum` of 0 — scoring a phrase-not-found failure as *perfect*. `word_miss_effective` is `None` for any degenerate, so degenerates can never score as wins.
- **`judge_unusable` is excluded, not penalised** — it means the *judge* failed (illegible page, boxed run not contiguous in the reading), not the locator, and its rate is already gated separately at 3%. Penalising it would blame the locator for a measurement failure. Do not confuse the non-contiguous case with `no_covered_words`, which is a real locator failure and *is* penalised.
- **Metric changes must be provably additive.** `tests/word_miss_smoke.py` re-scores the frozen sample and asserts every pre-existing number — `acc@1`, `acc@0`, and every verdict count in all six report sections — reproduces bit-identically. If that check fails you changed grading behaviour; fix the code, never the assertion. Its reference constants were rebased once, on 2026-07-31, for the judge alignment fix above — the one sanctioned exception, because there the task *was* to change grading behaviour. `tests/bbox_judge_regression.py` guards that fix: it re-derives the p64 pairing table, asserts the three pixel-verified cases score 0/0/≤1, and asserts `geom_confident is True` on all three so a "fix" that merely marks everything unconfident cannot pass.

**Changing scan geometry means bumping `review._LOCATE_VLM_CACHE_VERSION`.** The refined-box cache (`books/<slug>/locate_vlm.json`) is keyed on `(cache version, page_no, sha1(page_md), query text, alts, span)` — it does **not** include line geometry. A refined box is aligned onto detected line rects, so any change to `locate._scan_page_lines` silently leaves every existing entry encoding the OLD geometry, and nothing else will ever invalidate it. Measured: after `_split_tall_runs` landed, the frozen sample showed just ONE box moving — the fix was real but could not reach the boxes, because refinement was still being served from the pre-fix cache. Bumping the version moved 45 of 240 boxes (`perfect_rate` 0.783 -> 0.817, p90 1.0 -> 0.0). The cost is real but lazy and one-time: entries re-bill per page, only when a human actually re-reviews that page. A stale entry is silently wrong rather than visibly missing, which is why this is a bump-by-default rule.

Note `cmd_golden`/`tests/data/bbox_golden.json` is **not** an answer key — it snapshots the box a previously-`exact` case produced and gates on IoU against it. Do not conflate it with page truth.

Transcription requires `ANTHROPIC_API_KEY`, read from the environment or from `.env` at the project root (see `llm.load_env`).

## Workspace layout (the on-disk contract)

Everything revolves around `books/<slug>/` (gitignored), managed by `workspace.Workspace`:

- `source.pdf` — copied input
- `book.yaml` — metadata: title/author (LLM-proposed on first transcribe), `page_count`, optional `page_range`, optional `chapters: [{title, start_page}]` list that overrides heading-based chapter splitting at build time
- `pages/NNNN.png` — standard-res renders (long edge 1568 px); `pages/hires/` — 2576 px renders used on escalation
- `text/NNNN.md` — transcribed Markdown per page; `text/NNNN.json` — sidecar with model used, confidence, quality score, flags, `needs_review`, `starts_mid_paragraph`/`continues_next`, cost
- `out/` — final EPUB

A page counts as "done" when both its `.md` and `.json` exist (`Workspace.pages_done`); `transcribe` skips done pages unless `--force`.

## Pipeline architecture

Each module is one stage; they communicate only through the workspace files above, so stages can be rerun independently:

1. **`render.py`** — PyMuPDF rasterization plus `classify_pdf` (digital/scanned/mixed by embedded-text density) and `extract_embedded_text` (the validation oracle for digital PDFs).
2. **`transcribe.py` + `llm.py`** — per-page vision transcription via `client.messages.parse` with Pydantic `output_format` (`PageTranscription`). Pages are independent and run in a thread pool; cross-page paragraph joins are deferred to build time using the `continues_next`/`starts_mid_paragraph` sidecar fields. The elaborate Persian transcription rules (ی/ک codepoints, ZWNJ, verse blocks with ` --- ` hemistich separators, footnote syntax) live in `TRANSCRIBE_SYSTEM` in `llm.py` — the build step's parser depends on this output format. **Headings contract**: every string in the structured `headings` field must also appear in `text_md` as a `#`/`##`/`###` line; `validators.evaluate` enforces this (`missing_heading` issue), `transcribe.py` auto-promotes matching bold lines and retries once with a corrective hint on failure.
3. **`validators.py`** — deterministic quality scoring because LLM self-confidence is poorly calibrated. Core trick: compare char-sorted word multisets (cosine similarity) between the transcription and PyMuPDF's embedded text, which is immune to the extractor's broken word ordering and ligatures. Thresholds at the top of the file were measured empirically; a faithful digital-page transcription scores ~0.99, so 0.97 is already the escalation cutoff. Failing pages escalate to a hi-res render on the strong model; still-failing pages get `needs_review: true`.
4. **`qc.py`** — post-transcription QC. Auto mode runs an LLM verifier (`llm.qc_verify_page`) over risk-selected pages, writing findings + a suggested correction into the sidecar `qc` key (suggest-only — never overwrites `text_md`; the human decides per correction in the review UI). Each finding carries an optional `bbox` ([x0,y0,x1,y1] in 0–1000 image coordinates) estimated by the verifier. Pages with a pending suggestion are skipped on re-runs unless `qc --force`. Maintains `qc_history.json` at the project root (gitignored): append-only issue events with feature tags, from which per-feature lift weights bias future risk selection and review ordering. Schemas/contracts live in `TODO.md`.
5. **`review.py`** — stdlib `http.server` + jinja2 single-page web app (no external assets) showing page image beside editable Markdown, validator/QC findings, and the QC suggestion broken into per-correction **hunks** (whitespace-preserving token diff via `_derive_hunks`; context-anchored so hunks apply independently in any order — do not replace with a plain `split()` diff, it fails round-trip on real data). Each hunk gets Approve/Edit/Reject/Undo; page data is embedded as `<script type="application/json">` payloads (`_json_for_script` escapes `<`). Findings the verifier flagged without a usable fix — no suggestion, a suggestion identical to the current text, or an issue not linked to any hunk — still become an **edit-only** correction (synthesized by `_derive_finding_hunks`, id offset `100000`): Approve/Reject are disabled and only Edit is offered, prefilled with the flagged snippet; the Accept path records these as per-finding `human_edit` events. Located boxes are overlaid on the page image by a **tiered locator** in `locate.py` (`locate_queries`, memoized in `review._locate_queries_cached` with `page_md` in the key so an Accept invalidates stale boxes): Tier A **"match"** (blue) fuzzy-scores normalized word windows against `page.get_text('words')` — immune to RTL intra-word reordering (char-sorted equality) and Arabic↔Persian letterform variance (folding), gated per page on ≥30% Arabic-block words; Tier B **"layout"** (teal) maps the snippet's markdown char-offset onto the PDF's cumulative per-line char counts, so it works even on non-Unicode **cipher** text layers whose line rects are still real geometry (gated on a 0.5–2.0 pdf/md char-count ratio); Tier C **"scan"** (green) binarizes the rendered page, detects printed line and word-gap geometry, and maps the Markdown offset onto those ink regions, so image-only scans need no OCR or font model. Scan-sourced boxes are then upgraded to **"scan_vlm"** (dark green) via `locate.refine_scan_boxes`: a clean strip crop of the hit line(s) ±1 is transcribed line-by-line in one batched VLM call per page (`llm.read_strips`, Sonnet default, `review --bbox-refine-model` overrides), the query — plus the hunk's corrected text as a `Query.alts` alternate, since a wrong-word snippet is exactly what the image does *not* say — is re-aligned onto the detected word rects (line ID becomes exact, within-line placement a word-index lookup). Wrapped matches preserve ordered per-line `segments` plus a compatibility union envelope; the review UI renders those segments as one SVG overlay with complementary ripped edges at each RTL line break and no connector. Failures widen once to ±2 lines, then keep the plain scan box. Refinement never blocks the render path: `GET /` serves instantly using only already-cached results (`_ScanBoxRefiner.apply_cached`), a 4-worker background pipeline warms the cache in review order from server startup, and the browser polls `GET /boxes/<page>` (~2.5s, gated on a `BBOX_REFINE` flag; a muted RTL chip marks pages still pending) to swap upgraded boxes + payload geometry in place. Every outcome, including failures, is cached per book in versioned `locate_vlm.json` keys based on page text (Accept invalidates; negative entries never re-bill; geometry-version changes intentionally re-refine once); `--no-bbox-refine` or a missing API key skips refinement and review stays fully offline-usable. The locating query is capped to ~5 words (`_cap_words`) and the layout/scan tiers narrow each hit line to the covered word-rect sub-run (`_line_word_extent`/`_scan_line_extent`), so a box stays a zoomable fraction of the line rather than spanning it. Each tier self-gates per page; falling through all three yields the verifier's **"model"** `bbox` estimate (orange, dashed). Clicking any segment or its linked hunk/issue smooth-zooms to `segments[0]` (the upper-line beginning in Persian reading order), pulses the complete logical overlay, and marks the correction active; while zoomed, click-drag pans the image and a plain click (or Escape / background-click / re-click) zooms back out. Box plumbing stays 0–1 page fractions server-side → CSS percentages/SVG viewBox coordinates on `.img-wrap`. Selection surfaces pages flagged by either check: `needs_review` (validator- or QC-set) plus unreviewed pages whose validator `issues` stayed below the needs_review threshold. Review budget: only the worst `ceil(total/5)` flagged pages are surfaced (`review --all` bypasses); the rest are auto-accepted with `review_skipped: true`. A single **Accept** button persists the textarea to `text/NNNN.md` — the same file `build` reads — backing up the pre-edit text once to `text/NNNN.orig.md` (`Workspace.pages_done` ignores non-numeric stems for this reason) and reporting the per-correction tally (approved/edited/rejected/undecided). Per-hunk outcomes are recorded as QC history events; `review --reset` undoes a book's human decisions (keeps text edits) and strips its human events from history.

   Each correction also carries a live **placement chip** computed by `farsi2epub/placement.py` (`score_box`): the METRIC.md word-miss sum for its box — green at 0 ("on target"), amber 1–3, red 4+, muted grey "—" when it cannot be verified. `placement.py` is the geometry/metric core EXTRACTED out of `tests/bbox_score.py` (which now imports it) so the shipped UI and the offline harness cannot drift apart; the harness keeps only judging-specific code (truth-window search, verdicts, aggregation, `compare`, the CLI). Live scoring has no answer key, so its reference is the page's own **PDF word lines** where a usable text layer exists (independent of both the locator and the transcription) and the page Markdown otherwise — measured, the Markdown route is nearly always unconfident because a transcription reflows printed lines into paragraphs, so image-only scans and glyph ciphers legitimately show "—". It is a PLACEMENT check, never accuracy or confidence: a wrong transcription is invisible to it. Zero API calls, so it runs with no key; `GET /` uses cache lookups only (`_PlacementScorer.cached`) and the same background pipeline + `/boxes/<page>` poll that delivers refined boxes delivers the scores, with the box geometry in the cache key so a refined box that moved can never keep the old score.
6. **`epub.py`** — parses page Markdown into a block model, stitches cross-page paragraphs, splits chapters (by `book.yaml` `chapters` page numbers, else by `# ` headings), renders XHTML, and assembles an RTL EPUB with embedded Vazirmatn fonts (`assets/fonts/`). `normalize.py` runs first: conservative-only normalization (Arabic→Persian letterforms, kashida removal, punctuation spacing) — it deliberately never touches digits, ZWNJ placement, or newlines.

## Model choices (measured, don't casually revert)

- Default transcription model is Sonnet (`MODEL_STRONG` in `config.py`), not Haiku: measured Haiku first-pass failure was >90%, making the Haiku→Sonnet escalation ladder both worse and more expensive. Haiku is still used for the cheap metadata proposal and available via `--model`.
- Default input resolution is **hi-res (2576px, Sonnet 5's vision maximum)**, not the 1568px standard render: a std-res Sonnet pass was measured making character-level errors hi-res avoided (bidi-reversed dotted abbreviations like ه.ق → ق.ه, word transpositions, lost diacritics) — errors the word-bag validators are structurally blind to. `transcribe --res std` is the documented economy path (~30% cheaper/page; suits crisp large-print sources or very long books) and failing pages escalate to Sonnet + hi-res, so it degrades safely. Sidecars record `resolution` used per page.
- Sonnet is called with `thinking: {"type": "disabled"}` for transcription — it's a perception task, and adaptive thinking adds cost without accuracy.
- Cost is estimated in `config.estimate_cost` and tracked per page in sidecars; `--max-cost` aborts a run mid-flight.
